# FC-028 비회원 웹 참여와 캡처용 정산표

## FC-030 총무 앱 중심 공유 안내 (2026-11-01)

참여자는 응답 웹만 사용하고 총무가 확정 이미지를 전달한다. 공유 문구와 PNG 안내에서 앱의 금액 확인·보냈어요 입력을 요구하지 않는다.
금액·반올림·응답 API는 변경하지 않았다. 웹 Vitest 286개/22파일과 배포 빌드 통과. 실제 HTTPS 연결·이미지 저장/카카오 첨부는 별도 검증한다.

제품 결정: 총무 로그인 앱 유지, 참여자는 가입 없이 모바일 웹에서 이름과 차수 응답을 입력한다.
계약: jungsan_attack PR50·PR51의 API v18/19, GUEST_PARTICIPATION.md, SETTLEMENT_VIEWS.md.
원격 기준: profile main `87be8e6`. 기존 디자인·회원 흐름·목데이터 모드를 유지한다.

## 구현

### 확정 정산표 이미지 저장 (2026-10-31 추가 결정)

화면의 세로형 표는 유지한다. 금액 확정 후에만 ‘정산 금액이 확정되었습니다’ 안내와 전체 PNG 생성·저장 기능을 제공한다.
저장 이미지는 화면 너비와 별개로 참여자 전원을 가로 열에 배치하며 차수·항목·원 단위 조정·전체 부담·이미 결제·송금 안내를 보존한다.
맨 위에는 서버 transfers의 받는 사람별 **최종 보낼 금액**을 강조한다. 이미 결제한 사람의 전체 부담을 송금액으로 표시하지 않고, 송금이 없으면 ‘보낼 돈 없음’으로 표시한다. 여러 수취인이면 각각 표시하며 계산 근거는 그 아래로 분리한다.
금액 확정은 입금 완료를 의미하지 않는다. 이름과 참여자 ID로 동명이인을 구분하고 계좌·인증 토큰은 이미지에 포함하지 않는다.
기기 메모리 한도를 넘는 이미지는 일부를 잘라 저장하지 않고 명확한 오류를 안내한다. 이미지 공유는 사용자가 직접 선택한다.

- API 모드의 `/jungsan/j/{shareToken}`: 회원 확인 뒤 비회원은 이름·약관·차수 응답을 한 화면에서 제출한다.
- 쿠키 초기화는 동시에 한 번만 실행하고 완료 후 본인을 조회한다. 토큰/계좌를 URL·localStorage에 저장하지 않는다.
- 빈 이름 오류는 입력칸을 가리지 않으며 포커스가 돌아온다. 전 차수 선택, 재방문, 본인 수정, 제외·만료 안내를 제공한다.
- FC-029: 비회원 화면은 응답 제출·본인 수정만 제공한다. 개인 금액·계좌·보냈어요 화면은 제거하고 API 래퍼만 호환 유지한다. 401을 회원 로그인으로 강제 이동시키지 않는다.
- 로그인한 총무의 웹 정산방에서 ‘정산표 보기 · 캡처’를 누른다. 참여자를 세로 행으로 두고 차수별 이름·참여·안주·술·차수 부담을 표시한다. 전체 화면은 인원 제한 없이 이어지고, 캡처만 한 차수당 8명씩 나눈다. 원 단위 조정 뒤 전체 부담·이미 결제 요약과 송금 대상/금액을 붙인다. 서버 값을 재계산하거나 보낼 돈을 부담액과 동일시하지 않는다.
- 기존 html2canvas-pro로 각 장을 이미지로 열 수 있다. Excel 다운로드·이미지 서버 저장·카카오 자동 전송은 없다.
- 서버 금액을 표시하며 프론트에서 분배하지 않는다. 2026-10-31 CTO 결정: 음료는 기존처럼 안주에 포함해 함께 나누고 화면·이미지는 안주로만 표시한다. 음료 O/X 선택은 추가하지 않는다.
- 회원 ID 없는 참여자를 null로 유지한다. 같은 이름이어도 participantId로 구분하고 비회원에게 회원 알림/차단 계정을 만들지 않는다.

## 실행한 검증

- 전체 Vitest 282개 통과. 쿠키 초기화 경합·실패 재시도·guest API 경로·평문 오류·캡처 누락·동명이인/비회원 명단 회귀 포함. 10명 8+2행, 25명×5차수의 125개 조합과 조정·송금·전체 요약 누락/중복, 확정 조건과 이미지 메모리 한도를 검사한다.
- TypeScript 및 실제 API 주소·jeongsan 타깃 프로덕션 빌드 성공. 빌드의 큰 번들 경고는 남아 있다.
- 변경 파일 ESLint 검사 통과. 전체 lint는 기존 별도 서비스·픽셀 배경 등의 23개 오류/1개 경고로 실패하며 이 PR이 새로 만든 오류가 아니다.
- 브라우저의 로컬 가상 API 화면에서 빈 이름 → 재입력 → 참여 → 응답 변경 → 확정 금액 → 보냈어요를 확인했다.
- 세로형 320px 표와 이미지 생성 확인. 25명 전체 보기에서 각 차수/요약 25행, 송금 24행이 유지되고 캡처는 8행씩 나뉜다. 4명·25명 화면 모두 셀 넘침 0건을 확인했다.
- `qa/fc028-capture.png`는 가상 데이터로 실제 화면에서 생성한 첫 번째 장이다. 운영 계좌·참여 정보는 없다.
- `qa/fc028-vertical-25.png`는 25명 가상 데이터의 첫 8행 캡처다. 전체 표는 세로 스크롤로 모두 확인할 수 있다.
- `qa/fc028-horizontal.png`(1920×2096), `qa/fc028-horizontal-25.png`(5637×2128)는 320px 화면에서 생성·다운로드한 4명/25명 전체 PNG다. 맨 위 최종 송금액과 전원 열을 확인했다. 모두 가상 데이터다.
- 로컬 Windows의 테스트 임시 경로 접근 문제는 일반 실행 환경에서 재실행해 해결했다. 테스트를 건너뛰지 않았다.

## 재현과 배포 순서

개발 서버에 `VITE_JEONGSAN_API_BASE_URL=http://localhost:5177`을 설정하고 5177 포트로 실행한 다음
`/qa/fc028.html`을 연다. 이 페이지는 가상 응답 전용이며 운영 빌드 index에 포함하지 않는다.
모바일 폭에서 빈 이름·체크·재시도·확정 fixture·표 캡처를 재현할 수 있다.
`/qa/fc028.html?phone=1`은 검증 도구 모음만 숨긴 같은 참여 화면이다. 390px 스마트폰 폭에서
`qa/fc028-guest-phone.jpg`(첫 진입), `qa/fc028-guest-phone-selected.jpg`(이름·1차 알코올/2차 논알코올 선택)를 캡처했다.
운영 화면이나 실기기 캡처가 아니라 로컬 가상 데이터 화면이다. 음료 O/X 별도 선택은 현재 없으며 안주·음료 합산 배분 계약을 유지한다.

운영 빌드는 `VITE_APP_TARGET=jeongsan`, `VITE_JEONGSAN_API_BASE_URL=https://jungsan-api.devkdk.com`을 사용한다.
먼저 총무 앱의 nullable userId 호환 빌드를 확인하고, 백엔드 PR50/51의 검증된 SHA·DB 변경을 적용한 뒤 웹을 공개한다.
구버전 앱의 `SParticipant.userId: Long`은 비회원 명단에서 실패하므로 기존 TestFlight만으로 기능을 열지 않는다.
저장소에 현 운영 웹 호스팅의 배포 설정은 없다. 연결된 호스팅 대상·설정을 확인하기 전 다른 도메인이나 main에 임의 배포하지 않는다.

앱 안의 총무 정산표 진입·페이지 표시는 jungsan_app PR4에서 구현한다. 남은 범위: 실제 HTTPS 쿠키와 서버를 묶은 웹 E2E, iPad/Safari 저장·카카오 붙여넣기, 앱 정산표 실기기 확인, 운영 배포.
비회원 기기 이동 복구·계좌/결제자·메시지·스푼은 별도 후속이다. PR은 스터디용으로 열어둔다.

## FC-029 응답 전용 화면 · 총무 확인 (2026-11-01)

참여자는 이름과 차수별 불참/논알코올/알코올만 제출한다. 제출 후 ‘응답을 총무에게 보냈어요’와
‘이 창을 닫아도 돼요. 정산 결과는 총무가 알려드려요’를 표시한다. OPEN 동안 ‘내 응답 수정’ 가능.
회원으로 로그인한 채 링크를 열어도 기존 신원·회원 API로 응답하며 새 비회원 좌석을 만들지 않는다.
총무는 기존 방 진입을 유지한다. 기존 참여자의 수정은 join 재호출이 아니라 responses/me PUT이다.
목표 인원은 안내용이며 응답 명단 전체를 계산한다. 초과 인원 자동 제외·전원 응답 자동 확정은 없앴다.
총무가 명단에서 잘못된 응답자를 제외하고 ‘명단 확인 · 정산 확정’에서 예상 금액을 본 뒤 확정한다.
확정 전 미응답 DRANK/AUTO 경고·stale revision/hash 재확인·총무/결제자 제외 금지 유지.

390px 모바일 UI에서 빈 이름 오류 후 재입력, 응답 전송, 완료 안내, 응답 수정·재전송을 확인했다.
캡처: qa/fc028-response-only-form.jpg, qa/fc028-response-only-sent.jpg. 로컬 가상 자료이며 운영 화면이 아니다.
백엔드 PR52(API v20)와 함께 적용해야 한다. 기존 API의 개인 금액/송금 권한을 삭제한 변경은 아니다.
운영 미배포. 기존 PR은 스터디를 위해 열어둔다. 학습 상태 UNRECORDED.
