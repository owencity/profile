# 총 정산인원과 응답 현황

총무가 정산방에서 `총 정산인원 (나 포함)`을 따로 설정하거나 수정한다. 새 술자리를 만들 때 필수로 묻지 않으며, 각 차수의 예상 참석 인원과 구분한다. 예를 들어 차수별 예상 인원이 6·7·8명이고 총 정산인원이 7명이라면, 모든 차수에 응답한 사람이 6명일 때 `6/7명 응답`을 표시한다.

## 서버 계약

- `SettlementUnit.totalHeadcount: number | null`을 사용한다. 응답에서 누락됐거나 `null`이면 미설정이며, 기존 `headcount`나 차수별 `expectedHeadcount`로 대체하지 않는다.
- 저장 요청: `PUT /api/v1/gatherings/{gatheringId}/settlement-units/{settlementUnitId}/total-headcount`
- 요청 본문: `{ "totalHeadcount": 7 }`
- 성공 응답: 본문 없는 `204`.
- 이 정산방의 총무만 `OPEN` 상태에서 2~50 사이 정수를 저장한다. 서버도 동일한 권한·상태·범위 검증을 담당한다.
- 저장 성공 후 술자리를 다시 조회한다. 저장 실패 시 기존 화면 값을 바꾸지 않고 실패 이유를 표시한다. 저장은 성공했지만 재조회가 실패하면 그 두 결과를 구분해 새로고침을 안내한다.

## 화면과 인원 집계

총무와 비회원 모두 `participantId`별로 한 명씩 센다. 정산방의 모든 차수에 직접 또는 총무 대리 응답이 있어야 응답 수에 포함한다. 전 차수 불참도 응답이며, 미응답과 정산 때 자동으로 채운 `AUTO`는 제출로 세지 않는다.

총인원이 없으면 `N명 응답 · 총인원 미설정`을 표시한다. 설정 인원을 초과하더라도 실제 응답 수를 그대로 보여주고, 명단이 더 많으면 총무에게 검토를 안내한다. 목표 인원에 맞춰 사람을 제외하거나, 전원 응답만으로 정산을 확정하거나, 추가 참여를 막지 않는다. 확정은 총무가 명단과 예상 금액을 확인한 뒤 직접 한다. 이미 확정한 방은 총인원 수정 버튼을 제공하지 않는다.

차수 수정 화면은 해당 차수의 `expectedHeadcount`만 바꾼다. 총 정산인원 저장은 차수·참석 응답·송금 결과를 수정하지 않는다.

## 기존 흐름 유지

이 변경은 `95ce87c`의 차수별 예상 인원과 기존 차수 편집, `c0f055e`의 비회원 이름·응답 수정을 바탕으로 한다. `346c4d6`의 Apple 표시 이름과 계정별 약관 확인도 함께 반영했다.

참여자가 공유 링크를 열면 회원가입 없이 비회원 응답 화면을 사용한다. 기존 회원인지 확인하는 동안 대기하고, 비회원은 같은 브라우저의 쿠키로 자신의 이름·응답을 다시 수정한다. 이름으로 다른 사람의 응답을 선택해서 수정하는 방식은 추가하지 않았다. 최신 계정별 약관 확인은 로그인한 회원 화면에만 적용하며, 공개 약관·개인정보 안내와 비회원 링크를 막지 않는다.

## 확인 범위

모델 집계, 권한·상태·범위 검증, 204 저장과 재조회 실패, 차수 인원 독립, 비회원 응답과 Apple 약관을 포함해 전체 318개 테스트를 통과했다. TypeScript 검사, `VITE_APP_TARGET=jeongsan`과 운영 API 주소를 사용한 빌드, 변경한 TypeScript 파일의 ESLint도 통과했다. 빌드에는 기존 공용 앱 묶음이 500kB를 넘는다는 경고가 남아 있다. 실제 운영 반영과 모바일 브라우저 확인은 별도 배포·연결 검증 단계에서 수행한다.
