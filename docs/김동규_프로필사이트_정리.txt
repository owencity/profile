[카드 1] 외부 연동 아키텍처 — 폴링에서 이벤트 기반으로
카테고리: 아키텍처
기술스택: RabbitMQ, Spring Boot, Prometheus, Grafana, Loki
진행상태: 진행 중
시기: 2025.05~2026.07 내 (세부 시점 확인 필요)
소속: 명인코리아 · 유통 상품 관리 시스템 고도화

3줄 요약:
- 스케줄러 폴링 방식의 외부 연동을 RabbitMQ 기반 이벤트 발행 구조로
  전환해 동기/비동기 처리를 분리했습니다.
- 전송 실패 건은 자동 재시도 후 DLQ로 격리해, 유실 없이 사후 재처리할
  수 있게 설계했습니다.
- Prometheus·Loki·Grafana로 이상 징후를 규칙 기반으로 판정해 웹훅
  알람까지 연결했습니다.

구성도/순서도: (다이어그램 추가 예정 — 아직 없음)

문제:
스케줄러 폴링 방식은 자사몰 서버 장애 시 실패 건이 유실되고 수동 복구가
필요한 구조였습니다. 장애 1회가 연동 파이프라인 전체를 지연시켰습니다.

해결:
- 시스템 구성(동기/비동기 분리): RabbitMQ 기반 이벤트 발행 구조로 전환해
  비동기 실시간 연동을 구현했습니다.
- 외부 연동 순서도(실패 경로 중심): 전송 실패 시 자동으로 재시도하고,
  재시도 횟수를 초과한 건은 DLQ(Dead Letter Queue)로 격리해 유실 없이
  사후 재처리할 수 있도록 했습니다.
- 멱등성 설계: at-least-once 전달로 인한 중복 전송에 대비해 멱등 처리를
  설계했습니다. 재시도가 발생해도 중복 반영 없이 안전하게 처리됩니다.
- 운영: 최종 실패한 작업은 실패 사유를 로그로 남기고, 담당자가 화면에서
  직접 재시도할 수 있도록 제공했습니다.
- 관측성(규칙 판정 → 알람): Prometheus·Loki·Grafana 조합으로 이상 징후를
  규칙 기반으로 판정해 웹훅 알림으로 받는 구조를 만들었습니다. 장애를
  사후에 로그로 확인하는 방식에서 벗어났습니다.

결과 (Before → After):

재시도·알람까지 갖춘 구조로 전환했습니다.
